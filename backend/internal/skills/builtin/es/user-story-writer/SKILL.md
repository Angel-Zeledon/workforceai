# Historia de usuario

## Cuándo usarla
Para convertir una necesidad o un requisito en tareas que el equipo puede desarrollar.

## Pasos
1. Identifica quién es el usuario y qué necesidad tiene, según los datos de la tarea.
2. Escribe la historia con el formato: como [rol], quiero [acción], para [beneficio].
3. Añade entre tres y cinco criterios de aceptación verificables.
4. Indica dependencias y tamaño estimado solo si aparecen en los datos.

## Criterios de calidad
- Cada historia describe una sola capacidad entregable.
- El beneficio explica el valor para el usuario, no una tarea técnica.
- Cada criterio puede comprobarse con una prueba concreta.

## Límites
Deja las historias como propuesta para refinamiento del equipo. No asignes responsables ni puntos de esfuerzo sin datos que lo respalden.
