# Notas de versión

## Cuándo usarla
Para comunicar a usuarios o al equipo qué cambió en una versión.

## Pasos
1. Agrupa los cambios en novedades, mejoras, correcciones y cambios que rompen compatibilidad.
2. Escribe cada punto en una frase con el beneficio para el usuario, sin jerga interna.
3. Destaca al inicio la novedad principal y la fecha de lanzamiento si está en los datos.
4. Añade una sección de acciones necesarias para quien deba migrar o reconfigurar algo.

## Criterios de calidad
- Cada cambio citado aparece en los datos de la tarea; no se inventan mejoras.
- Números de versión y fechas coinciden exactamente con la fuente.
- Cada cambio ocupa idealmente una sola línea.

## Límites
Deja las notas como borrador para revisión de producto y comunicación. No publiques ni anuncies nada sin aprobación humana.
