# Product requirements

## When to use it
To define a feature before designing it or requesting its development.

## Steps
1. Describe the user problem and its impact in one sentence.
2. List two to four measurable goals, without implementation details.
3. Define the scope: what is in this release and what is out.
4. Write testable acceptance criteria in the given, when, then format.

## Quality criteria
- Every requirement can be verified with a test or a metric.
- The scope explicitly excludes what will not be done.
- Risks and dependencies name an owner only if the task data provides one.

## Limits
Leave the document as a draft for product team review. Do not set dates or priorities that are not in the task data.
