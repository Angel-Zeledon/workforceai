# Usability test plan

## When to use it

Before observing real users complete tasks in a flow, prototype or screen, to find friction and decide on changes. Use `templates/usability-test-plan.md` as the structure.

## Steps

1. Write one to three goals, each as a question the test must answer, for example whether the person finds the payment option without help.
2. Define three to five tasks with a realistic scenario. The task wording must not reveal the exact path, and each task has an observable result that marks it as completed.
3. Describe the participant profile: role, experience with the product and exclusion criteria, plus the number of people per profile in each round.
4. Write the session script: welcome, a statement that the product is being tested and not the person, tasks in order, one question after each task and a close with open questions.
5. Define the metrics: completion rate, time on task, errors and their severity, and a perceived ease scale if used. Set what result counts as a problem.
6. State how findings are recorded and prioritized: what was observed, how many participants experienced it and its severity, so they can become changes.

## Quality criteria

- Each goal can be answered with the data the test will collect.
- Task wording does not reveal the solution.
- The script asks participants to think aloud without leading their answers.
- Metrics and their success thresholds are defined before the session.

## Limits

This is a plan for review by the product or research team. It does not recruit participants or contact people, does not record sessions without explicit consent and does not invent results or sample sizes. Participant data is recorded anonymously.
