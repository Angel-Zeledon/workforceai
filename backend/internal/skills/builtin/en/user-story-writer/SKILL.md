# User story

## When to use it
To turn a need or a requirement into tasks the team can build.

## Steps
1. Identify who the user is and what need they have, based on the task data.
2. Write the story as: as a [role], I want [action], so that [benefit].
3. Add three to five testable acceptance criteria.
4. Note dependencies and estimated size only if they appear in the data.

## Quality criteria
- Each story describes one deliverable capability.
- The benefit explains the value to the user, not a technical task.
- Each criterion can be checked with a concrete test.

## Limits
Leave the stories as a proposal for team refinement. Do not assign owners or effort points without data that supports them.
