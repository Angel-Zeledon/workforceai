# Release notes

## When to use it
To tell users or the team what changed in a version.

## Steps
1. Group the changes into new features, improvements, fixes and breaking changes.
2. Write each item in one sentence with the benefit to the user, free of internal jargon.
3. Lead with the main new feature and the release date if the data includes it.
4. Add a section listing the actions needed by anyone who must migrate or reconfigure something.

## Quality criteria
- Every change mentioned appears in the task data; no improvements are invented.
- Version numbers and dates match the source exactly.
- Each change ideally fits on a single line.

## Limits
Leave the notes as a draft for product and communications review. Do not publish or announce anything without human approval.
