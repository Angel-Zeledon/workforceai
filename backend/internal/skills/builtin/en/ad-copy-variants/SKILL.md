# Ad copy variants for A/B tests

## When to use it
When ad messages must be tested for the same audience and offer, before uploading them to an ad platform. Use `templates/variants.csv` to record each asset.

## Steps
1. Define the ad objective, the audience and the single offer being tested.
2. Check the character limit of each field in the reference table in this document, and write each asset within that limit.
3. Create three to five variants that change only one variable at a time: the angle, the headline, the proof or the call to action.
4. Label each variant with its hypothesis, for example "savings benefit versus time benefit".
5. Count the characters of each asset and rewrite any that exceed the limit.
6. Propose the test plan: main metric, sample size to be set with the platform data, and the criterion for deciding.

## Reference character limits

| Format | Field | Indicative limit |
|---|---|---|
| Paid search ad | Headline | 30 characters |
| Paid search ad | Description | 90 characters |
| Image-based social network ad | Primary text | 125 characters visible before "see more" |
| Image-based social network ad | Headline | 40 characters |
| Professional network ad | Introductory text | 150 characters |
| Professional network ad | Headline | 70 characters |

These limits are indicative and may change. Confirm them in each platform's current documentation before uploading the assets.

## Quality criteria
- No asset exceeds the limit of its field.
- The variants differ in one clear variable, and each has its hypothesis written down.
- Each variant promises only what the offer can deliver, with no figures that were not provided.
- Each asset has a concrete benefit or a clear call to action.

## Limits
It does not publish ads or assign budget. It does not invent discounts, deadlines, prizes, figures, testimonials or guarantees, and it does not present results from past tests that are not in the data.
