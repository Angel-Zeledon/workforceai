Configuration reference

All configuration comes from the environment. The backend (Go) loads and validates its variables at startup and refuses to boot with inconsistent values; the runtime (Python) reads its own when it needs them; the frontend only has build arguments. The defaults on this page come from the code.

How configuration is loaded

The backend reads the environment in config.Load and calls Validate before starting. Booleans accept strconv.ParseBool values (true, false, 1, 0...) and an invalid value aborts startup. For numeric and duration variables, a missing, non-numeric or non-positive value is replaced by the default. Durations use Go syntax (30s, 5m, 1h). Lists are comma-separated.

In the Required column, Yes means the process does not start without the variable; Conditional means it depends on another variable; No means there is a default or the feature turns off.

Authentication, CORS and proxy

With AUTH_ENABLED=false the backend runs in demo mode (fixed organization, no login). With AUTH_ENABLED=true it enables JWT, RBAC and per-organization isolation: org_id comes from the token. Validate rejects a JWT_SECRET shorter than 32 bytes, a missing DATABASE_URL and an asterisk in ALLOWED_ORIGINS.

VariableDefaultRequiredMeaning
AUTH_ENABLEDfalseNoEnables accounts, JWT, RBAC and multi-tenancy. The production compose sets it to true.
JWT_SECRETemptyConditionalAccess token signing key; at least 32 bytes; required with AUTH_ENABLED=true. Rotating it invalidates sessions.
ALLOWED_ORIGINSemptyConditionalAllowed origins for CORS and WebSocket, without trailing slash. Empty without auth means *; empty with auth, same-origin only. * is rejected with auth.
AUTH_COOKIE_SECUREtrueNoSecure attribute of the refresh token cookie. Only turned off for local plain-HTTP development.
AUTH_COOKIE_NAMEemptyNoCookie name, to avoid collisions between stacks sharing a host.
TRUSTED_PROXIESemptyNoCIDRs or IPs of proxies whose X-Forwarded-For is honoured (for example for rate limiting). An invalid value aborts startup.
ENABLE_DEMO_RESETfalseNoRegisters POST /api/v1/demo/reset. Must stay false in production.
KILL_SWITCHemptyNofreeze or lockdown: a process-wide override no API call can lift. Re-read on SIGHUP.
UI_BASE_URLemptyNoFrontend URL the browser is redirected to after the OAuth callback.

Rewards and coins

The coin system rewards completed work. REWARDS_RULES lets you replace the rules with a JSON whose fields match the names below; invalid values are rejected and the backend falls back to the default rules instead of applying a half-changed economy. REWARDS_WELCOME_COINS grants welcome coins once to every organization on first use.

{
  "enabled": true,
  "base": { "S": 5, "M": 10, "L": 20, "XL": 40 },
  "default_complexity": "M",
  "first_try_bonus_pct": 50,
  "rework_pct": 50,
  "project_base": 20,
  "project_per_task": 2,
  "project_max": 100,
  "min_project_tasks": 2
}
VariableDefaultRequiredMeaning
REWARDS_ENABLEDtrueNofalse, 0 or off turns coin earning off entirely.
REWARDS_RULESemptyNoJSON with rules: enabled, base (S, M, L, XL), default_complexity, first_try_bonus_pct, rework_pct, project_base, project_per_task, project_max, min_project_tasks.
REWARDS_WELCOME_COINS1000NoWelcome coins each organization receives once on first use. 0 disables it.
Tip. The example shows the default rules. Include in REWARDS_RULES only the fields you want to change.

Runtime: model providers and keys

The runtime requires at least one configured provider, except with SIMULATION=true. It supports deepseek, anthropic and an OpenAI-compatible endpoint (custom). On error, timeout or rate limit it retries and moves to the next allowed provider. With ALLOWED_PROVIDERS no data reaches an excluded provider, not even as a fallback. Provider keys are secrets: never put them in images or in the repository.

CUSTOM_LLM_BASE_URLemptyConditionalBase URL of an OpenAI-compatible endpoint. Enables the custom provider.
CUSTOM_LLM_API_KEY / CUSTOM_LLM_MODELemptyNoOptional key and model name of the custom endpoint.
CUSTOM_PRICE_IN_PER_M / CUSTOM_PRICE_OUT_PER_MSonnet rateNoUSD per million tokens of the custom endpoint; may be 0 for a local model.
MODELemptyNoLegacy: provider/model applies to that provider; an unprefixed name applies to the primary.
MODEL_PROVIDER_ORDERdeepseek,anthropic,customNoGlobal fallback order. MODEL_PROVIDER_ORDER_<ROLE> also exists per agent role or for PLAN, CONSULT and SYNTHESIZE.

Connections, email, sandbox and storage

Without CONNECTIONS_KEK no live credential can be stored: the system fails closed, and simulated connections keep working. The KEK is base64 of 32 random bytes; CONNECTIONS_KEK_PREVIOUS lets old data keys be unwrapped during a rotation. The code sandbox is optional and needs the sandbox-runner service, which is given access to the Docker socket; read the security documentation first.

Rate limits

Authentication and command rate limits are built into the backend and the current configuration exposes no variables to tune them. What is configurable is TRUSTED_PROXIES: only the X-Forwarded-For header from those proxies is used to identify the client, so behind Caddy you should list the proxy network; without it, the client IP seen is the proxy's.

Frontend: build arguments

The frontend is compiled with standalone output. NEXT_PUBLIC_* variables are baked in at build time as Dockerfile arguments (ARG); they are not read at runtime. Leaving them empty gives the recommended single-domain behavior: relative /api/v1 paths and a WebSocket derived from window.location.

docker build \
  --build-arg NEXT_PUBLIC_API_URL=https://app.example.com/api/v1 \
  --build-arg NEXT_PUBLIC_WS_URL=wss://app.example.com/ws \
  -t aiworkforce-frontend ./frontend
Build argumentDefaultRequiredMeaning
NEXT_PUBLIC_API_URLemptyNoAbsolute API base URL (for example https://app.example.com/api/v1). Empty: relative path.
NEXT_PUBLIC_WS_URLemptyNoAbsolute WebSocket URL (wss://app.example.com/ws). Empty: derived from window.location.
NEXT_PUBLIC_MOCKemptyNotrue runs the frontend with mock data, without a backend.

Email verification and trial accounts

Two optional sign-in features. Email verification needs a working SMTP: with EMAIL_VERIFICATION=true and no valid SMTP the backend refuses to start, so a half-configured server cannot lock anyone out. Trial accounts let people try the app without signing up and expire on their own.

VariableDefaultMeaning
EMAIL_VERIFICATIONfalseNew accounts must open a one-time link sent to their address before they can sign in. Needs AUTH_ENABLED, UI_BASE_URL and SMTP_* (or EMAIL_DEV_LOG).
EMAIL_DEV_LOGfalseDevelopment only: verification links are written to the log instead of being sent.
SMTP_HOSTSMTP server. Required with EMAIL_VERIFICATION unless EMAIL_DEV_LOG is on.
SMTP_PORT465465 uses implicit TLS; 587 uses STARTTLS.
SMTP_TLStls (465) / starttlstls, starttls or none (none only for a local relay).
SMTP_USER / SMTP_PASSCredentials for the SMTP server; set both or neither.
SMTP_FROMSender, e.g. AI Workforce OS <no-reply@example.com>.
TRIAL_ENABLEDfalseTurns on POST /auth/trial: throwaway accounts with their own organization (needs AUTH_ENABLED).
TRIAL_TTL_HOURS24How long a trial account works.
TRIAL_PER_IP_PER_DAY3Trial accounts one client address may create per day.
TRIAL_GLOBAL_PER_DAY300Trial accounts created per day, all addresses together.
TRIAL_EMAIL_DOMAINprueba.invalidDomain of the generated trial addresses (no mailbox behind it).
