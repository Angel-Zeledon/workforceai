Skills format

A skill is reusable know-how that an agent loads when it needs it: a folder with a SKILL.md file and optional text resources, in the open Agent Skills format. This page is for anyone who writes, imports or reviews skills. Since it is plain prompt text plus one gateway tool, it works the same with every model provider.

What a skill package is#

A package is a folder whose only required file is SKILL.md: a YAML frontmatter block followed by markdown instructions. It may include supporting files such as templates, examples, reference documents or scripts, always as text.

Each version stores its files in the organization's Drive, at /Shared/Skills/<name>/v<n>/, and the database keeps the manifest: path, size and sha256 of each file. Versions are immutable; restoring an old version creates a new version with the same content.

SKILL.md frontmatter#

SKILL.md must be valid UTF-8, start with a --- line and close the block with another one. The instructions after the frontmatter cannot be empty.

The parser understands a small subset of YAML, on purpose:

  • Scalars, quoted strings and > or | blocks.
  • Inline or block lists.
  • A single level of nested map, only for metadata.
  • It rejects anchors, aliases, tags, inline maps and tabs in indentation.
FieldRequiredRule or limit
nameYesPattern ^[a-z0-9-]{1,64}$. Unique per organization and immutable once created.
descriptionYesUp to 1024 characters. It is what the agent reads to decide whether to use the skill: say what it does and when to use it.
licenseNoFree text.
compatibilityNoFree text; preserved on export.
allowed-toolsNoUp to 20 entries. Informational: it never grants tools.
metadataNoKey-to-text map, up to 30 entries (for example category).

Note

Other top-level scalar keys are preserved on import and export (up to 20 keys and 300 bytes per value), so a round trip loses nothing. The in-app editor does not show compatibility or those extra keys: saving from the editor drops them.

Built-in starter skills#

The backend ships a catalog of starter skills embedded in the binary, in Spanish and English, in the same format as an import. There are 55 per language today, including bank-reconciliation, b2b-proposal, service-contract-review, month-end-close, client-email and project-plan.

The first time an organization opens the library, they are created as active in its language. If the organization already has any skill, even a deleted one, none are created, and deleted starters do not come back. Role templates declare default_skills (names only) and agents of that role receive them without needing an assignment.

Lifecycle and review#

A skill is in one of four statuses: draft, in_review, active or disabled. Members (skills:write permission) create drafts, edit, import and restore versions. Administrators (skills:review permission) approve, reject, disable and delete.

  • An import always enters in_review.
  • If a member edits an active skill, the new version lands in in_review and agents keep using the approved one. If an administrator edits it, the edit counts as the review and it becomes active.
  • A review names the version the reviewer read: if it is no longer current, it fails with stale_review. File hashes are checked again before activation.
  • A rejection stores a note and returns the skill to draft, or keeps it active with the previous approved version when there is one.
  • Deletion is soft and removes assignments. Creating another skill with the same name brings it back with a new version.

Scanning, import and export#

Every saved version is scanned and the warnings are stored for the reviewer. The scan informs; it does not decide: the reviewer sees everything before approving.

  • injection: a file's injection score exceeds the threshold.
  • script: the package ships executable files as text (py, js, sh).
  • allowed_tools: the frontmatter declares allowed-tools.
  • import_note: the import adjusted something, for example it skipped an empty file.
  1. Import a .zip or a single SKILL.md with POST /api/v1/skills/import (multipart field file).
  2. Validation is strict: it rejects absolute paths or paths with .., backslashes, drive letters, symlinks and special files, encrypted entries, duplicates that differ only in case, and zip bombs. It strips a single wrapper folder and ignores __MACOSX, .DS_Store and Thumbs.db.
  3. An administrator reviews the version and approves or rejects it.
  4. To take it out, GET /api/v1/skills/{id}/export returns a deterministic zip in the standard layout (<name>/SKILL.md plus resources, no executable bits), or only SKILL.md with ?format=md.

Note

Import from a URL deliberately does not exist: it would need an SSRF-safe downloader.

Assignment to agents#

An assignment links a skill to an agent through PUT and DELETE on /api/v1/agents/{id}/skills/{skillId}, with the agents:write permission. There are also role defaults: the names in a role template's default_skills reach every agent of that role without an explicit assignment.

An agent only receives a skill if it is assigned (or is a default of its role), is neither deleted nor disabled, and has an approved version. While an edit waits for review, the approved version is served. In any other case the load is denied with skill_not_available.

How skills reach the model#

Disclosure is progressive, in two steps. On every run, the backend adds to the request only the name and description of the skills the agent can use, with caps: at most 12 skills, 240 characters per description and 3000 bytes in total. The runtime renders them in the prompt with an explicit rule: a skill guides how to work and never grants tools, connections, permissions, autonomy or approvals.

If a skill applies, the agent asks for it with a tool request. The Tool Gateway serves it as a native read tool, subject to the kill switch, pause and audit, and answers with the approved version's body without frontmatter plus the file list. With file it returns a single resource.

Limits and cleaning of loaded text#

Once loaded, the skill enters the task context with several safeguards:

  • The text travels in its own channel (loaded_skills) as trusted organization configuration, inside dedicated delimiters, because a person approved that exact version.
  • It is still cleaned (invisible characters, credentials, forged delimiters) and scored for injection.
  • It is bounded in the backend (24,000 characters per answer, 4 loads per task) and again in the runtime (3 skills, 12,000 characters each, 20,000 in total).
  • Scripts are inert text: running them requires the code tool, with human approval.
