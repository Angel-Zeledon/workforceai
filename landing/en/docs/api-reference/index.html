API Reference

The Go backend exposes a REST API under /api/v1 and a WebSocket at /ws. This reference summarizes authentication, conventions and the main routes as registered in the router; example bodies are representative, not exhaustive.

Base URL and versioning

All REST routes hang under /api/v1; the version is part of the path. The WebSocket (/ws) and the root health check (/healthz) live outside that prefix. Bodies are JSON (UTF-8), except drive uploads, which use the raw body.

With AUTH_ENABLED=false (demo mode) no authentication is required and everything runs on a fixed organization. With authentication on, every route except /healthz, /auth/* and the OAuth callback requires a token. Examples use localhost:8080; substitute your host.

# Base URL (local default)
http://localhost:8080/api/v1
# WebSocket (outside /api/v1)
ws://localhost:8080/ws

# Health (no auth)
curl http://localhost:8080/healthz
# {"status":"ok","runtime":"up","runtime_mode":"simulation"}

Authentication

Login returns an access token (a JWT, 15 minutes by default) sent in the Authorization: Bearer header. The refresh token never appears in the JSON body: it lives in an HttpOnly, SameSite=Strict cookie named wfai_refresh, scoped to the /api/v1/auth path. Endpoints that use that cookie (refresh and logout) also require the X-WFAI-CSRF header.

The organization comes from the token, never from a parameter. Roles are owner, admin, member and viewer, and each route requires a specific permission. The WebSocket accepts the token as ?access_token=.

# Log in: the access token is in the body, the refresh token in an HttpOnly cookie
curl -i -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"<password>"}'
# {"token_type":"Bearer","access_token":"<token>","expires_in":900,
#  "expires_at":"...","user":{...},"org_id":"<org id>","role":"owner"}

# Call the API with the access token
curl http://localhost:8080/api/v1/agents -H 'Authorization: Bearer <token>'

# Renew the session (cookie + CSRF header)
curl -X POST http://localhost:8080/api/v1/auth/refresh \
  -b 'wfai_refresh=<cookie value>' -H 'X-WFAI-CSRF: 1'
Method and pathDescription
POST /auth/registerCreates an organization and an owner user. Body: email, password, name, org_name.
POST /auth/loginSigns in. Body: email, password, optional org_id.
POST /auth/refreshRotates the refresh token (cookie + X-WFAI-CSRF) and returns a new access token.
POST /auth/logoutEnds the current session and clears the cookie. Returns 204.
POST /auth/logout-allRevokes all of the user's sessions.
POST /auth/switch-orgNew session in another organization. Body: org_id.
GET /auth/me, GET /auth/configCurrent user; public configuration (whether login is on).
GET/POST /auth/members, PATCH/DELETE /auth/members/{id}List, add, change the role of, or remove members.
GET/POST /invitations, DELETE /invitations/{id}Invitation management. POST /auth/invitations/accept accepts them.

Errors, limits and conventions

Errors return JSON with a meaningful HTTP status. Most routes use {"error": "message"}; connections and controls add a stable code field; authentication routes and permission failures use {"error": {"code", "message"}}. A 500 does not expose internal detail.

There is no global pagination. Each listing defines its own parameters: GET /activity accepts limit (default 100, maximum 1000); GET /conversations/{id}/messages accepts limit (maximum 200) and before, and sets the X-Has-More and X-Next-Before headers; chats and history use limit and offset; memory accepts limit and q. JSON bodies are capped at 1 MiB by default (413 when exceeded). Authentication routes have per-IP rate limits (429).

CodeMeaning
400Invalid body or parameters.
401Missing, invalid or expired token.
403The role lacks the permission, or the CSRF check failed.
404Resource does not exist in your organization.
409State conflict (for example, a different expected version).
413Body too large.
429Authentication rate limit.
Tip. POST /messages, POST /shop/purchases and other side-effecting operations accept Idempotency-Key; a retry returns the first result with the Idempotent-Replayed header.

Requests, chat, tasks and reports

POST /requests is asynchronous: it answers 202 with the request_id and progress arrives over the WebSocket. budget_cap_usd is optional and sets a hard cap for that request.

# Submit a request (asynchronous: 202 + id, progress arrives over WebSocket)
curl -X POST http://localhost:8080/api/v1/requests \
  -H 'Authorization: Bearer <token>' -H 'Content-Type: application/json' \
  -d '{"text":"Prepare a $50,000 proposal for ACME","budget_cap_usd":5}'
# 202 {"request_id":"<id>"}

# Chat message to the office (idempotent with the header)
curl -X POST http://localhost:8080/api/v1/messages \
  -H 'Authorization: Bearer <token>' -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: 7d1e...' \
  -d '{"conversation":"office","text":"Who is free today?"}'
# 202 turn object; replies arrive as chat.message events

POST /requestsCreates a request. Body: text, optional budget_cap_usd.

GET /requests/{id}/cost, /estimateAccumulated cost and upfront estimate.
POST /requests/{id}/confirm, PUT /requests/{id}/budgetConfirm an estimate; change the cap.
POST /messagesChat message. Body: conversation (office by default), text, attachments.
GET /conversations, GET /conversations/{id}/messagesConversations and messages.
POST /conversations/{id}/messagesPost to a specific conversation.

GET /activity, GET /metrics, GET /budgetActivity, metrics and budget.

Approvals and agents

Deciding an approval is a privileged action: admin or owner only. When approving, you can also request a standing permission (always_allow) for internal, reversible actions. An approval can require two distinct people.

# List pending approvals
curl 'http://localhost:8080/api/v1/approvals?status=pending' \
  -H 'Authorization: Bearer <token>'

# Approve (admin or owner)
curl -X POST http://localhost:8080/api/v1/approvals/<id>/decision \
  -H 'Authorization: Bearer <token>' -H 'Content-Type: application/json' \
  -d '{"decision":"approve","note":"ok"}'
# 200 the updated approval; "decision" is "approve" or "reject"
Method and pathDescription
GET /approvalsList; status filter (pending, approved, rejected).
POST /approvals/{id}/decisionBody: decision (approve or reject), note, always_allow, always_allow_any_agent, always_allow_days.
POST /approvals/batchDecide several approvals of a project.
GET /agents, GET /agents/{id}, GET /agents/{id}/detailAgents: state, tools, permissions and autonomy.
GET/PUT /agents/{id}/profile, GET /agents/{id}/tracesVersioned work profile and reasoning traces.
GET /agents/{id}/memory, DELETE /agents/{id}/memory/{docId}Long-term memory.
GET /role-templates, POST /agents/from-templateHire an agent from a template.
PUT /agents/{id}/budget, POST /agents/{id}/controlBudget and pause or resume.

Projects and skills

A project is a multi-node plan with a budget. The cycle is create a draft, edit the plan, estimate and validate, then launch. Skills are reusable instructions, versioned and reviewed before they become active.

# Create a draft project, then launch it
curl -X POST http://localhost:8080/api/v1/projects/draft \
  -H 'Authorization: Bearer <token>' -H 'Content-Type: application/json' \
  -d '{ ...project fields... }'
curl -X POST http://localhost:8080/api/v1/projects/<id>/launch \
  -H 'Authorization: Bearer <token>' -H 'Content-Type: application/json' -d '{}'
Method and pathDescription
GET /projects, POST /projects/draft, POST /projects/from-templateList and create drafts.
GET /projects/{id}, /snapshot, /health, /approvalsProject state, health and approvals.
PATCH /projects/{id}/plan, POST /estimate, /validate, /launchEdit, estimate, validate and launch.
POST /projects/{id}/control, PUT /projects/{id}/budgetControl execution and set the budget.
POST /projects/{id}/nodes/{nodeId}/retry, /skip, /replanRecover a node.
GET/POST /project-templates, GET/PUT/DELETE /project-templates/{id}Templates with versions.
GET/POST /skills, GET/PUT /skills/{id}Skill catalog and editing.
POST /skills/{id}/submit, /review, /disableReview workflow; review and disable need the reviewer permission.
GET/PUT/DELETE /agents/{id}/skills[/{skillId}]Assign skills to an agent.

Shop, rewards and drive

Finished tasks and projects pay coins exactly once. The shop spends coins atomically and with an audit entry. The drive stores the organization's files with versions, a trash and grants.

curl http://localhost:8080/api/v1/rewards/wallet -H 'Authorization: Bearer <token>'
curl -X POST http://localhost:8080/api/v1/shop/purchases \
  -H 'Authorization: Bearer <token>' -H 'Content-Type: application/json' \
  -d '{"item_id":"<item id>","idempotency_key":"<unique key>"}'
Method and pathDescription
GET /rewards/wallet, /rewards/ledger, /rewards/rulesBalance, ledger and payout rules.
GET /shop/catalog, GET /shop/stateCatalog and state (inventory, equipped).
POST /shop/purchasesBuy. Body: item_id, idempotency_key.
PUT/DELETE /agents/{id}/equipment/{slot}Equip or remove a character item.
PUT/DELETE /office/items/{slot}Place or remove an office item.
GET /drive/list, /drive/search, /drive/usage, /drive/trashBrowse the drive.
PUT /drive/upload?path=Upload or version a file (raw body).
GET /drive/files/{id}, /content, /text, /preview, /versions, /diffRead a file and its history.
POST /drive/folders, /drive/files/{id}/move, DELETE /drive/files/{id}Organize and delete (to the trash).

Connections, controls and settings

Connections store encrypted credentials for external services; without CONNECTIONS_KEK no real credentials can be saved. Controls let you pause agents, put the organization in read-only mode or trigger a kill switch.

# Pause or resume one agent
curl -X POST http://localhost:8080/api/v1/agents/<id>/control \
  -H 'Authorization: Bearer <token>' -H 'Content-Type: application/json' \
  -d '{"action":"pause","drain":"graceful","reason":"maintenance"}'

# Organization kill switch (level: none | freeze | lockdown)
curl -X POST http://localhost:8080/api/v1/org/controls/kill-switch \
  -H 'Authorization: Bearer <token>' -H 'Content-Type: application/json' \
  -d '{"level":"freeze","reason":"incident"}'

POST /connections/{id}/oauth/start, /testStart OAuth and test the connection.
GET /connections/oauth/callbackPublic OAuth callback, verified by a single-use state.
GET/PUT /org/controls, POST /org/controls/kill-switch, /releaseRead-only mode and kill switch (none, freeze, lockdown).

WebSocket and health

GET /ws opens the organization's event channel. On connect it sends hello with the agent list and then every domain event. The client only reads: the server ignores incoming messages, and there are no topic subscriptions or replay. If the token expires, the server closes with code 4401 and the client must reconnect with a fresh token.

GET /healthz and GET /api/v1/healthz need no authentication. They return status, runtime (up or down) and, when the runtime answers, runtime_mode (simulation or live).

# Browsers cannot set headers on a WebSocket: pass the token in the query string
wscat -c 'ws://localhost:8080/ws?access_token=<token>'
